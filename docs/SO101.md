# 二、完整流程：双臂 SO101（数据采集 → π0.5 微调 → RLT）

SO101 流程与 Cobot Magic 共用 π0.5、RL Token（Stage 1）和 Stage 2 学习器，但**不依赖 ROS、CAN 和 Piper 代码**：
机械臂通过 LeRobot 0.1.0 的 Feetech 总线直接控制。两套流程的文件、配置、环境和启动脚本互不重叠
（见“与 Cobot Magic 的隔离”）。

```text
0 环境 ─▶ 1 探测/配置硬件 ─▶ 2 标定 ─▶ 3 示教采集 ─▶ 4 归一化 ─▶ 5 π0.5 微调 ─▶ 6 纯 π0.5 推理
      ─▶ 7 Stage 1 RL Token ─▶ 8 动作增量统计 ─▶ 9 紧凑推理服务 ─▶ 10 Stage 2 在线 RL（含人工接管）
```

所有命令在仓库根目录执行（`export RLT_ROOT=$PWD`）。

## 0. 环境（SO101 主机，无需 ROS / sudo）

```bash
git clone --recursive https://github.com/ROI-su7/RLT.git ~/RLT && cd ~/RLT
bash env/install_all.sh --so101        # 03 openpi/.venv → 04 .venv-rlt → 05 基座权重 → 06 Feetech SDK
bash env/verify.sh --so101
```

- 串口权限：`sudo usermod -aG dialout $USER`；RLT 键盘（evdev）：`sudo usermod -aG input $USER`（之后重新登录）。
  不想加 `input` 组时用文件按键：`RLINF_SO101_KEYBOARD=file`，然后 `echo t >> ~/.so101_rlt_keys`（也适合 SSH 远程操作）。
- 训练服务器只需 `bash env/install_all.sh --no-ros`。

## 1. 探测与配置硬件

每套 SO101 = 一条 leader（5 V 供电）+ 一条 follower（12 V 供电），各一块 USB 舵机板，6 个 STS3215（ID 1–6）。

```bash
so101/.venv/bin/python so101/probe.py --out so101/probes/set1.json     # 只接左侧一套时
so101/.venv/bin/python so101/probe.py --out so101/probes/set2.json     # 换接右侧一套后
so101/.venv/bin/python so101/probe.py --merge so101/probes/set1.json so101/probes/set2.json \
    --left set1 --right set2 --out so101/dual_arm.yaml
```

- `probe.py` 只读，不写舵机；串口按 USB 序列号（`/dev/serial/by-id`）写入 `dual_arm.yaml`，换 USB 口或换主机后依然有效。
  主从按舵机供电电压区分（leader ≈ 5 V，follower ≈ 12 V）。
- 打开 `so101/dual_arm.yaml`，把三路相机 `cam_high / cam_left_wrist / cam_right_wrist` 的 `device` 填成
  `/dev/v4l/by-id/...`（或 `by-path`）。相机名不要改：π0.5 数据配置按这三个名字读图。
- 仓库里的 `dual_arm.yaml` / `probes/` 是 2026-10-30 在开发机上读到的两套臂（set1 主 5B14031917 / 从 5B14033136，
  set2 主 5B14112595 / 从 5B14110654；set1=左、set2=右为假定）。换成你自己的臂时重新探测即可。

## 2. 标定（每条臂一次，在接臂的主机上）

```bash
openpi/.venv/bin/python so101/cli.py calibrate      # 按提示摆姿势；结果写入 so101/calibration/（不入库）
openpi/.venv/bin/python so101/cli.py teleoperate    # 自检：左右 leader 带动左右 follower
```

## 3. 示教采集（LeRobot v2.1 数据集）

```bash
openpi/.venv/bin/python so101/cli.py record --task "<任务描述>" --episodes 50 --episode-time 60 \
    --root ~/rlt_data/lerobot_data/so101_dual       # 键：右箭头结束本条，左箭头重录，Esc 停止
ln -s ~/rlt_data/lerobot_data openpi/lerobot_data    # 训练配置读 ./lerobot_data/so101_dual
```

状态/动作 12 维 `[左臂 6, 右臂 6]`，每臂 `shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper`，
LeRobot 标定后的角度（度），夹爪 0–100；30 fps；三路相机。`--task` 文本就是之后 π0.5 和 RLT 的提示词。

## 4–5. 归一化与 π0.5 微调

```bash
cd openpi
.venv/bin/python scripts/compute_so101_parquet_norm_stats.py --dataset-root lerobot_data/so101_dual
XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 .venv/bin/python scripts/train.py pi05_so101_dual_lora --exp-name=so101_v1 --no-wandb-enabled
```

- `pi05_so101_dual_lora`：单张 24 GB；`pi05_so101_dual`：全参（多卡或 ≥ 40 GB）。
- 数据变换 `LeRobotSo101DataConfig`：10 个关节取相对当前状态的增量，两个夹爪保持绝对值；提示词取自录制的 task。

## 6. 纯 π0.5 推理（不带 RL，可选）

## 7. Stage 1：RL Token

```bash
cd openpi && source RLinf/.venv-rlt/bin/activate

torchrun --standalone --nproc-per-node=<GPU 数> RLinf/toolkits/realworld_check/train_piper_rlt_token_native_jax.py \
  --jax-checkpoint checkpoints/pi05_so101_dual_lora/so101_v1/<step> --dataset-dir lerobot_data/so101_dual \
  --output-dir ~/rlt_checkpoints/so101_rlt_token --config-name pi05_so101_dual_lora --steps 10000 --accumulate 8 \
  [--cpu-offload]       # 只有一张 24 GB 卡时加上：参数/梯度/优化器放 CPU，能跑但慢
```

## 8. 动作增量统计（填入 Stage 2 配置）

## 9–10. Stage 2：真机 RLT

```bash
export RLINF_SO101_TASK="<任务描述>"                        # 与录制时的 --task 一致
export RLINF_STAGE1_RLT_TOKEN=~/rlt_checkpoints/so101_rlt_token/step_10000/rlt_token.pt
# 终端 1：紧凑推理服务（参考动作 + z_rl）
RLINF_PI05_JAX_DIR=$PWD/openpi/checkpoints/pi05_so101_dual_lora/so101_v1/<step> RLINF_ROBOT_RLT_TOKEN=$RLINF_STAGE1_RLT_TOKEN \
  bash openpi/RLinf/examples/embodiment/serve_so101_rlt_compact.sh
# 终端 2：RLT（先只读检查四条串口和相机配置）
bash openpi/RLinf/examples/embodiment/run_so101_rlt_stage2.sh
```

按键与 Cobot Magic 相同：

| 键 | 作用 |
|---|---|
| `I` | 开始 / 恢复策略控制（接管中按 I 也会交还给策略） |
| `B` | 打开采集门：之后完整的动作块进入回放 |
| `T` | **人工接管 / 交还**（见下） |
| `C` / `X` | 本条成功 / 失败，停在 HOLD |
| 空格 | HOLD（保持当前位置） |
| `H` | 在 HOLD 时让从臂慢速回到初始位（第一次复位时记录的位置） |

### 人工接管（参考 Evo-RLT）

实现：`openpi/RLinf/rlinf/envs/realworld/so101/takeover.py`、`rlt_wrapper.py`。做法与
[Evo-RLT](https://github.com/MINT-SJTU/Evo-RLT) 的 `PolicySyncDualArmExecutor` 和干预状态机一致：

1. **策略执行时**，两条 leader 保持力矩，并收到与 follower 相同的目标位置（leader 跟着 follower 走）。
   因此任何时刻按 T，leader 都已经在 follower 的位置上，接管没有跳变。
2. **按 T**：leader 卸力矩（可以手拖），follower 跟随 leader；前 0.5 s（`takeover_blend_s`）从最后一个策略动作
   线性过渡到 leader 位姿。这些步作为人工动作写入回放（`intervene_action`）。
3. **再按 T（或 I）**：leader 在当前位置重新上力矩，被打断的策略动作块剩余部分作废（不计入回放），
   下一个动作块重新规划。
4. 状态码与 Evo-RLT 相同：POLICY 0、ACTIVE 1、RELEASE 2。

与 Cobot Magic 的操作规则相同：只在接触前（还能看到 ≥ 1 mm 偏差时）接管；已经接触时直接按 X。
调度、续训（`RLINF_STAGE2_RESUME_DIR` / `RLINF_REPLAY_LOAD_PATH`）和监控停止线与 Cobot Magic 一致，见 [PIPELINE.md](PIPELINE.md)。

### 无硬件检查整条链路

`RLINF_SO101_HARDWARE=sim` 用模拟双臂（`SimSo101Arms`）运行同一套 Stage 2；采集可用 `so101/cli.py record --mock`。

## 单位与参数（相对 Cobot Magic 的换算）

Stage 2 配置 `realworld_so101_rlt_stage2_ac_mlp.yaml` 是独立文件（不继承 Piper 配置）：

- 12 维动作，每臂 6 维（5 关节 + 夹爪）；夹爪位置由 `rlinf/utils/arm_layout.py` 按维度推出（14 维仍是 Piper 布局）。
- 30 Hz，动作块 C = 10，stride 2；无 RTC 桥（`rtc_enabled: false`）、无接头位姿检测（`head_pose_dim: 0`）。
- 弧度 / 米 → 度 / 夹爪 0–100：Actor 修正上限 `[1, 1, 1, 2, 2]` 度、夹爪 2；探索噪声 0.17 度、夹爪 0.6；
  目标策略平滑 0.23 / 0.46 度。这些是按 Piper 值换算的起点，需要在真机上调。

## 与 Cobot Magic 的隔离

| | Cobot Magic | SO101 |
|---|---|---|
| 机器人代码 | `cobot_magic/`（ROS、四 CAN） | `so101/`（LeRobot） |
| RLinf 环境 | `rlinf/envs/realworld/piper/`，`PiperWireEnv-v1` | `rlinf/envs/realworld/so101/`，`So101DualEnv-v1` |
| π0.5 配置 | `pi05_connect_strings` 等（Aloha 14 维） | `pi05_so101_dual(_lora)`（12 维） |
| Stage 2 配置 | `realworld_piper_rlt_stage2_*.yaml` | `realworld_so101_rlt_stage2_ac_mlp.yaml` |
| 启动脚本 | `start_piper_ros_tmux.sh`、`run_piper_rlt_stage2_single.sh`、`serve_piper_rlt_compact.sh` | `run_so101_rlt_stage2.sh`、`serve_so101_rlt_compact.sh` |
| 安装 | `install_all.sh`（01–05） | `install_all.sh --so101`（03–06） |

两者共享的只有通用部分（π0.5 模型、RL Token、Stage 2 学习器与回放）。为支持 12 维动作，共享代码中把夹爪位置
从写死的“每 7 维”改为按维度推出（`rlinf/utils/arm_layout.py`），14 维的结果与之前完全相同；紧凑推理服务、
Stage 1 训练和增量统计工具新增的参数（`--state-dim`、`--prompt`、`--cpu-offload`、`--action-dim`）默认值即
Piper 原行为。同一台机器上不要同时跑两套 Stage 2（共用 GPU、Ray 端口 6379 和推理端口 6006）。

## 验证记录

2026-10-30 在一台 RTX 4090（24 GB）开发机上，从干净克隆（`env/install_all.sh --only 06` + `env/verify.sh --so101`）验证：

|---|---|---|
| 硬件探测 | 两套真实 SO101 分两次接入，`probe.py` 只读 | 4 块板、24 个 STS3215 全部读到，主从按电压正确区分 |
| 采集 | `cli.py record --mock`（LeRobot 模拟总线与相机） | 3 条 / 358 帧，12 维状态与动作 + 三路视频 |
| 归一化、π0.5 LoRA 训练 | `compute_so101_parquet_norm_stats.py`、`train.py pi05_so101_dual_lora` 4 步 | 正常保存 checkpoint（只验证链路，不代表效果） |
| 纯 π0.5 推理 | `infer.py --mock --dummy` | 跑通 |
| Stage 1 | `--cpu-offload`，单卡 2 步 | loss 3.09 → 2.82，写出 `rlt_token.pt` |
| 增量统计 | `--action-dim 12` | 正常输出 12 维 q01/q99 |
| 紧凑推理服务 | `serve_so101_rlt_compact.sh` | 12 维状态，返回参考动作与 z_rl |
| Stage 2 | `RLINF_SO101_HARDWARE=sim`，文件按键：I→B→T→T→C，再 I→B→T→X | 两轮完整结束；375 条转移、675 次学习器更新；接管期间 `intervention_rate` 升到 1.0，`takeover_as_failure` 生效；C 记为奖励 1；无报错 |
| 单元测试 | `env/verify.sh --so101` | 375 个 RLinf 测试（含 11 个 SO101 环境/接管测试）+ openpi SO101 测试全部通过 |

**尚未验证**：真实双臂上的标定、录制、相机，以及 leader 臂力矩开关与镜像在真机上的手感；Stage 2 的换算参数需要在真机上调。
